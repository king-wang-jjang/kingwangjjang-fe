# EVAL.md - 품질 평가 기준

이 문서는 Kingwangjjang FE 프로젝트의 결과물이 "잘 만들어졌는지" 판단하기 위한 기준과 테스트 시나리오를 정의합니다.

## 1. 품질 평가 기준 (Quality Criteria)

### 1.1. 기능적 정확성 (Functional Accuracy)

- **기준**: `SPEC.md`에 명시된 모든 기능적 요구사항이 의도대로 정확하게 동작해야 한다.
- **평가 방법**: 아래 `테스트 시나리오`를 수행하여 모든 케이스를 통과하는지 확인.

### 1.2. 성능 (Performance)

- **기준**: 주요 웹 성능 지표(Core Web Vitals)를 충족해야 한다.
- **평가 방법**:
    - **LCP (Largest Contentful Paint)**: 2.5초 이내 (게시글 목록, 상세 페이지 기준)
    - **FID (First Input Delay)**: 100ms 이내 (버튼 클릭, 입력 필드 등)
    - **CLS (Cumulative Layout Shift)**: 0.1 이하 (광고나 이미지 로딩으로 인한 레이아웃 밀림)
    - **도구**: Lighthouse, `next/analytics`

### 1.3. 코드 품질 (Code Quality)

- **기준**: `CONTRIBUTING.md`에 정의된 코드 스타일과 컨벤션을 준수해야 한다.
- **평가 방법**:
    - `yarn lint` 실행 시 에러가 발생하지 않아야 한다.
    - `yarn fm:check` 실행 시 포매팅 문제가 없어야 한다.
    - 코드 리뷰를 통해 가독성, 유지보수성, 중복 코드 여부를 평가한다.

### 1.4. UI/UX 일관성 및 사용성

- **기준**:
    - `src/theme`에 정의된 디자인 시스템(색상, 폰트, 간격)을 일관되게 사용해야 한다.
    - 모든 인터랙티브 요소는 명확한 `hover`, `focus`, `active` 상태를 가져야 한다.
    - 반응형 디자인이 모든 주요 디바이스(모바일, 태블릿, 데스크톱)에서 깨짐 없이 동작해야 한다.
- **평가 방법**: 다양한 화면 크기에서 UI를 직접 테스트하고, 디자인 시안과의 일치도를 비교한다.

## 2. 테스트 시나리오 (Test Scenarios)

### 시나리오 1: 신규 사용자 회원가입 및 첫 게시글 작성

| 단계 | 행동 | 예상 결과 | 성공/실패 |
| :--- | :--- | :--- | :--- |
| 1 | 회원가입 페이지로 이동 | 회원가입 폼(이메일, 비밀번호, 이름)이 표시된다. | |
| 2 | 유효하지 않은 이메일 형식 입력 | "유효한 이메일 형식이 아닙니다." 에러 메시지 표시. | |
| 3 | 유효한 정보 입력 후 '가입' 버튼 클릭 | 가입이 완료되고 로그인 페이지로 리디렉션된다. | |
| 4 | 가입한 정보로 로그인 | 로그인이 성공하고 헤더에 사용자 프로필이 표시된다. | |
| 5 | 게시글 작성 페이지로 이동 | 제목과 내용 입력 필드가 있는 에디터가 표시된다. | |
| 6 | 내용 입력 후 '등록' 버튼 클릭 | "게시글이 성공적으로 등록되었습니다." 메시지 표시 및 게시글 상세 페이지로 이동. | |
| 7 | 게시판 목록 페이지로 이동 | 방금 작성한 게시글이 목록 최상단에 표시된다. | |

### 시나리오 2: 기존 사용자 게시글 조회 및 상호작용

| 단계 | 행동 | 예상 결과 | 성공/실패 |
| :--- | :--- | :--- | :--- |
| 1 | 로그인하지 않고 게시판 페이지 접근 | 게시글 목록이 정상적으로 표시된다. | |
| 2 | 스크롤을 페이지 맨 아래로 이동 | 로딩 스피너가 잠시 보인 후, 다음 페이지의 게시글들이 추가로 로드된다. | |
| 3 | 특정 게시글 클릭 | 해당 게시글의 상세 페이지로 이동하고, 조회수가 1 증가한다. | |
| 4 | '좋아요' 버튼 클릭 (비로그인 상태) | "로그인이 필요합니다." 메시지와 함께 로그인 페이지로 이동 유도. | |
| 5 | 로그인 후 '좋아요' 버튼 클릭 | '좋아요' 수가 1 증가하고 버튼이 활성 상태로 변경된다. | |
| 6 | 다시 '좋아요' 버튼 클릭 | '좋아요' 수가 1 감소하고 버튼이 비활성 상태로 돌아온다. | |

### 시나리오 3: 에러 핸들링

| 단계 | 행동 | 예상 결과 | 성공/실패 |
| :--- | :--- | :--- | :--- |
| 1 | 존재하지 않는 URL 경로로 접근 (e.g., `/xyz`) | "페이지를 찾을 수 없습니다" 내용의 404 에러 페이지가 표시된다. | |
| 2 | 개발자 도구에서 네트워크를 오프라인으로 설정 | "네트워크 연결을 확인해주세요." 와 같은 메시지가 표시된다. | |
| 3 | 서버 API가 500 에러를 반환하도록 모킹 | "서버에 문제가 발생했습니다." 내용의 에러 페이지 또는 컴포넌트가 표시된다. | |
| 4 | 권한이 없는 페이지 접근 시도 (e.g., 일반 유저가 관리자 페이지 접근) | "접근 권한이 없습니다." 내용의 403 에러 페이지가 표시된다. | |
