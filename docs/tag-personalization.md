# 태그 기반 개인 추천 v1

## 사용자 경험

- `/board`에 전체 / 맞춤 추천을 제공한다. 태그·사이트·카테고리 필터는 두 모드에서 모두 우선 적용한다.
- 추천 후보는 서버에서 찾고 정렬한다. 첫 요청에서 최대 120개의 게시글 ID와 추천 이유를 확정하고 30개씩 본문을 불러온다. 활동 기록이 바뀌어도 현재 목록은 재정렬하지 않으며, 새 추천 보기 또는 필터 변경 시 갱신한다.
- 후보는 최근 7일 게시글 중 최신 300개, 인기 300개, 상위 관심 태그 10개별 최대 50개를 합쳐 구성한다. 첫 버전은 이 제한된 후보군에서 추천하며 전체 과거 게시글을 탐색하지 않는다.
- 처음 방문하면 최근 인기글과 관심 태그 선택을 제공한다. 추천 이유, 관심 없음, 관심 태그 추가/삭제, 태그 숨김/해제, 개인화 끄기, 기록 초기화를 제공한다.

## 관심도

- 태그 선택 1점, 게시글 펼치기 2점, 원문 열기 3점, 좋아요 5점. 같은 글은 UTC 날짜별 가장 강한 행동만 반영한다. 태그가 여러 개인 글은 점수를 나눈다.
- 관심 없음은 해당 글을 30일간 제외하고 태그에 -4점을 나누어 반영한다. 단순 노출, 닫기, 댓글 열기는 관심으로 기록하지 않는다.
- 행동은 최근 30일, 최대 500건. 14일 반감기를 적용한다. 직접 선택한 관심 태그는 10점의 지속적 가중치를 갖고, 숨긴 태그는 후보에서 제외한다.
- 태그는 NFKC 정규화, 앞의 # 및 공백 제거, 대소문자 무시로 일치시킨다. 의미가 비슷한 태그를 임의로 합치지 않는다.
- 추천 점수는 정규화된 관심도 60%, 최신성 25%, 인기도 15%. 관심사가 없으면 최신성·인기도로 시작한다. 가능한 경우 매 5번째 자리에 관심 분야 밖의 글을 섞고, 동일 출처 연속 노출을 줄인다. 최근 읽은 글은 감점한다.

## 저장과 동기화

- 비회원: 버전이 있는 로컬스토리지 문서에 제한된 행동과 명시적 설정 저장. 저장 실패 시 메모리에서 계속 동작한다. 익명 관심사는 추천 요청에만 전달하며 서버 DB에 저장하지 않는다.
- 회원: board-service의 계정별 추천 프로필 테이블을 사용한다. 계정 키는 인증된 공급자와 사용자 ID로 결정한다. 브라우저가 보낸 계정 ID는 받지 않는다.
- 회원 행동의 게시글 태그는 서버 게시글에서 확인한다. 각 변경에 고유 ID를 부여하고 서버의 버전 조건 갱신으로 중복·동시 요청을 처리한다. 초기화 시각 이전의 늦은 행동은 다시 반영하지 않는다.
- 회원 프로필은 메모리에, 미전송 변경만 계정별 로컬 큐에 저장한다. 로그인 확인 중에는 기록하지 않는다. 계정 변경 시 이전 응답·캐시를 격리한다. 통신 실패 시 큐를 유지하고 재시도한다.
- `로그인하고 저장`을 누르거나 로그인 후 관심사 관리의 `비로그인 관심사 가져오기`를 직접 선택했을 때만 기록을 가져온다. 최초 병합 계정에 가져오기 요청을 연결해 계정 변경 시 중복 이전을 막는다. 병합 완료 응답을 받은 뒤 비회원 저장 내용을 비운다. 기존 계정의 숨김 설정을 우선한다. 일반 로그인은 기존 서버 관심사를 사용한다.
- 서버 응답에는 `Cache-Control: private, no-store`를 사용한다. 만료된 행동은 읽기·갱신 시 제외한다. 서버의 시간당 정리 작업이 비활성 계정에서도 만료 기록을 물리적으로 삭제한다. 명시적으로 선택한 태그는 초기화/해제 시까지 유지한다.

## 로그인 안내

- 비회원이 서로 다른 글 5개 이상을 열어본 후 맞춤 추천 영역에 작은 안내를 표시한다.
- 세션당 한 번 표시하고, 닫으면 30일간 표시하지 않는다. 팝업이나 강제 로그인은 사용하지 않는다.
- 문구: “이 브라우저에서 쌓은 관심사를 다른 기기에서도 이어보세요.” / 로그인하고 저장 / 닫기.
- 로그인 전에 같은 사이트의 복귀 경로를 저장하고 인증 완료 후 복귀한다. 일반 로그인 동작은 유지한다.

## 검증

- 점수 감쇠, 중복 행동, 다중 태그, 관심 없음, 숨김, 초기화, 저장 손상/실패.
- 회원 계정 격리, 동시 갱신, 재전송, 익명 비저장, 실제 게시글 태그 확인, 병합 재시도.
- 후보 필터, 관심 분야 밖 탐색, 안정된 페이지 순서, 로그인 안내 빈도와 복귀.
- 프론트엔드 전체 검사 및 백엔드 테스트. 운영에서는 추천 클릭·원문 이동·관심 없음·출처 다양성을 함께 확인한다.
